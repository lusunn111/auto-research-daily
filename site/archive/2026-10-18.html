Setting（研究设定）
在测试阶段，对流匹配VLA策略进行重复采样；仅在关键决策状态触发额外采样，并用基于JEPA的潜世界模型对候选动作块排序后执行；在真实双臂机器人与RoboTwin 2.0、LIBERO仿真中评测。
Motivation（研究动机）
流匹配VLA策略具有随机性，同一观测下不同噪声种子会产生质量不同的动作块；但部署时策略通常只执行单个样本，且无法估计其质量。在精细操作中，执行次优动作可能不可逆地破坏任务进展。
Insight（核心洞察）
可利用策略自身的随机性：仅当状态关键时才重复采样，并让潜世界模型在统一潜空间中同时预测动作条件下的未来隐状态与任务增量进度，从而避免像素重建和目标图像依赖，实现高效且更准确的候选动作块排序。
Challenge（技术挑战）
  • 不同噪声种子产生的动作块质量不一，策略无法判断哪个最可能成功
  • 错误动作会不可逆地改变物理世界或累积误差导致分布漂移
  • 验证需要额外计算，必须控制延迟以适应实时VLA推理
  • 增量进度估计依赖任务语义，而潜动力学建模应与任务无关，二者需解耦
  • 真实部署中采样与验证会增加时延
Analyze（问题分析）
作者通过经验观察指出，策略方差在接触密集区域更高，失败最可能发生在这些区域；所提出的触发值随任务难度和策略内部不确定性变化。触发设计上，用两个初始样本分别度量动作块内时间变化与跨样本方差，并将二者作为互补信号分析：时间分量Status AUC更高（0.704对0.694），跨样本分量Variance Correlation更高（0.877对0.789）。验证器设计上，作者将任务条件进度估计与任务无关潜动力学建模分离，避免任务语义泄漏进潜动力学模型。
Method（方法）
  • 训练无关的双轴触发：用两个初始样本度量块内时间变化与跨样本方差，以检测关键状态
  • 触发后额外采样，共获得K个候选动作块
  • 验证器基于JEPA世界模型：预训练视觉编码器加动作条件自回归预测器，在潜空间预测未来隐状态
  • 引入具身特定的状态编码器与动作编码器，并将动作块均分为M个子块进行多步潜空间滚动，兼顾更密集监督与推理开销
  • 引入任务特定可学习查询token，条件化增量进度预测，将任务条件进度估计与任务无关潜动力学建模分离
  • 验证器联合优化潜预测与进度估计，进度损失为Huber回归损失加成对排序损失
  • 按预测的增量进度对候选动作块排序并选择执行
Experiments（实验）
  • 真实世界三个精细任务（笔插入、移液、苹果放置）：平均完成分数从50.8%提升到65.5%，每个触发决策在单张RTX 4090上增加326 ms采样与验证时延（不含触发时延）
  • 真实世界相对基础策略提升14.7个百分点，优于VLM验证器和像素级世界模型验证器；RoboMonkey在粗定位任务（如苹果放置）有竞争力但在精细操作上表现不佳；GPC-RANK在真实观测上较强但在测试时生成帧上性能下降
  • RoboTwin 2.0干净设置：平均成功率从66.4%提升到73.6%；随机化设置：从62.8%提升到69.6%；基础策略为Hy-Embodied-0.5-VLA，评测五个基线成功率较低的精细任务
  • LIBERO：从96.9%提升到97.6%
  • 延迟分析：三级优化（含KV缓存，其带来最大延迟降低）将每个触发决策的验证延迟降至326 ms；触发使用两个样本，每个决策增加14 ms延迟
Limitations（局限）
  • 重复采样与选择难以有效引导预训练VLA模型；验证器效果依赖底层策略候选的多样性与质量，而不同随机种子的采样多样性仍相对有限
  • 使用冻结的视觉编码器虽降低训练成本并保留预训练表示，但这些表示并非为操作进度估计显式优化，可能忽略物体构型、接触条件或任务完成度的细微变化
  • 未来可研究在JEPA框架内将进度估计作为优化目标，学习编码器–预测器对

基于JEPA的潜世界模型通过预测动作条件未来潜状态与任务进度变化来排序候选动作块：a JEPA-based latent world model ranks candidate action chunks by predicting action-conditioned future latent states and the corresponding changes in task progress.

Setting（研究设定）
在VLM主干上构建教师-学生非对称双分支架构的机器人操作策略：在线分支仅接收当前观测与语言指令，以因果方式生成潜动作；EMA教师分支在训练时额外接收未来观测，并读取目标潜动作。训练数据混合了带动作标注的机器人演示与不带动作的人类视频（ego clips），且不设置独立的潜动作或世界模型预训练阶段。
Motivation（研究动机）
现有VLA策略依赖带动作标注的机器人演示，缺少对未来的显式预测机制，因此难以利用无动作视频，并且容易对演示条件过拟合，削弱泛化与鲁棒性；已有的潜动作模型或潜世界模型通常先单独预训练，再适配至机器人策略。这种多阶段流程引入额外检查点与优化边界，而且不能保证学到的潜表示对最终动作解码器有用。
Insight（核心洞察）
把时序预测作为VLA策略的中心接口：利用非对称的时序信息差，让未来视觉证据只在训练时作为教师信号，从而使在线策略保持因果；同时将潜动作、未来视觉特征位移与流匹配动作生成耦合在同一个端到端训练图中，并且在与推理时都不需要额外的潜动作世界模型检查点。
Challenge（技术挑战）
  • 动作解码器通常直接由机器人轨迹学习，其隐藏状态未必表示动作即将引起的短时视觉变化，策略缺少执行前的显式内部预测
  • 无动作视频很丰富，但缺少机器人动作标注，需要把时序变化压缩成紧凑潜码以利用这些数据
  • 多阶段预训练潜动作或世界模型会引入额外检查点与优化边界，而且与最终动作解码器的目标不完全一致
  • EMA教师分支增加训练显存，未来特征条件化拖慢DiT动作专家收敛，延长整体训练时间
Analyze（问题分析）
作者指出现有VLA的动作接口直接从机器人轨迹学习，隐藏状态不一定表示短时视觉变化；同时指出两阶段潜动作或世界模型预训练带来额外计算与优化边界问题，并据此提出共享模块、带掩码损失的联合训练图，以混合机器人片段与无动作人类片段。
Method（方法）
  • 采用非对称VLM分支：在线的X-VLM只接收当前观测与指令，产生latent-X token，并由小型transformer预测器映射为预测潜动作；EMA的Y-VLM接收当前与未来观测，作为训练时的教师读取对应的目标潜动作
  • 冻结DINO编码器把当前与未来图像表示为空间特征网格，新初始化的潜世界解码器预测特征位移ΔF_t=F_{t+1}-F_t
  • 将vlm-jepa与delta-lwm耦合：用预测的潜动作预测未来视觉特征，在推理时以这些特征引导动作生成
  • 流匹配动作专家在预测未来特征与VLM上下文的条件下生成机器人动作块
  • 统一端到端训练：在机器人片段上使用L_robot=L_flow+λ_T L_temp+λ_W L_world；在无动作ego片段上使用L_ego=λ_T L_temp+λ_W L_world，以样本级有效性掩码决定哪些终端头参与，共享在线VLM、潜动作预测器与世界解码器，混合批次或微批的掩码损失求和为一次共享模块更新
  • 训练时使用EMA目标分支作为稳定回归目标，无需单独训练外部教师；推理时移除EMA教师分支，从而保持部署策略轻量
Experiments（实验）
  • 在LIBERO、LIBERO-Plus与SimplerEnv上进行实验，并在Franka Research 3与RevoTron上进行真实世界操作实验
  • LIBERO-Plus零样本迁移结果表显示TS-WAM参数量为1.2B，七个扰动类别的成功率分别为Camera 50.5、Robot 60.1、Language 77.5、Light 94.4、Background 91.5、Noise 76.1、Layout 79.6，整体75.7，表中作为对比的VLA-JEPA、π0、UniVLA等方法给出了各自数值

Limitations（局限）
  • 引入额外训练成本：EMA教师分支在训练时适度增加GPU显存消耗
  • 以预测未来特征作为DiT动作专家的条件会拖慢其收敛，导致整体训练时间更长；作者提出用数据划分降低显存、用共享注意力提升动作专家收敛效率

Setting（研究设定）

Motivation（研究动机）
VLA策略通常以动作预测作为主要监督信号，LA和FV等辅助目标虽被证明有益，但它们与动作预测竞争同一训练预算。作者质疑：在固定预算下，将大量训练样本分配给辅助目标而非继续用于动作预测，是否反而能提升策略学习效果。
Insight（核心洞察）

Challenge（技术挑战）

Analyze（问题分析）

Setting（研究设定）
闭环机器人操作部署中，VLA 模型在每个控制步将高分辨率、常为多视角的图像编码为数百个视觉 token，主导 LLM 主干的计算与延迟；目标是免训练地在推理时减少视觉 token 数量而保持任务成功率。
Motivation（研究动机）
VLA 闭环部署受推理效率限制，视觉 token 数量远超短任务文本 token；现有 VLM 式 token 压缩面向单次视觉理解，忽略控制决策中 token 重要性由任务决定、且各步预算变化大这两点，静态指标与固定预算会浪费计算或丢弃控制关键 token。
Insight（核心洞察）
视觉 token 的重要性应由任务到视觉的注意力决定，而非通用视觉显著性；且每步可保留的 token 数应随重要性分布的集中程度自适应变化，用 inverse-Simpson 均匀度指标加滑动窗口在线校准来设定压缩率。
Challenge（技术挑战）
  • 决策关键 token 由任务而非通用显著性决定
  • 各步 token 预算差异大，静态指标和固定预算不合适
  • 复用/缓存方法有跨步状态与缓存管理开销，实际时延收益可能落后于 FLOPs 降低
  • 学习式方案需要训练且绑定特定主干
Analyze（问题分析）
论文指出 VLA 与单图 VLM、固定帧序列视频 VLM 不同：视觉 token 是序列决策过程的组成部分，其重要性随任务与动作变化；并对比三类压缩路线（剪枝、合并、复用/缓存），说明现有方法在免训练、任务条件化、自适应压缩率三方面的不足，据此提出两阶段框架。
Method（方法）
  • 第一阶段：用任务到视觉的注意力给每个视觉 token 打重要性分数（task-conditioned attention signal）
  • 第二阶段（核心贡献）：由重要性分布的集中程度决定每步保留多少 token，用 inverse-Simpson 均匀度指标度量
  • 用在线滑动窗口校准自适应压缩率，在决策需要处多花 token、不需要处更激进剪枝
  • 整体为免训练、每步独立剪枝、不使用缓存的 plug-and-play 框架
  • 在 VLA 模型的 LLM 主干前减少视觉 token 序列长度以降低计算与延迟
Experiments（实验）
  • 在 OpenVLA、OpenVLA-OFT（LIBERO）与 CogACT-base（SIMPLER）上评测，并在实体 Franka Research 3 机器人上验证
  • 仿真中 LLM 主干 FLOPs 降低 35-59%，动作延迟降低 9-32%（1.09×-1.46× 加速），同时保持任务成功
  • 与现有 plug-and-play token 压缩/剪枝/复用基线相比取得相当或更好的效率-性能折中
  • 真机上端到端延迟降低 20%（1.25× 加速），成功率相当；结论称控制频率最多提升 25%，与未压缩基线差距在 0.6 点以内
  • 多样性指标消融（LIBERO-Goal / LIBERO-10）：inverse-Simpson 在成功率与 token 用量上优于 Shannon 与 Gini
  • 部分对比方法（标 * 者）无法复现，引用原论文结果仅作参考；全部实验在单张 NVIDIA RTX 4090 上进行
Limitations（局限）
  • 作者提出将机器人特有结构（如 3D 几何或本体感知）纳入重要性估计是未来方向，暗示当前重要性估计未利用这些信息
  • 作者提出将自适应剪枝与复用或 early-exit 策略结合是未来方向，暗示当前方法未结合这些手段
  • 标 * 的对比方法未能在作者环境中复现，其结果仅引自原论文

Setting（研究设定）
MLLM 作为无人机的唯一决策者，在每个步骤接收自我中心视觉观测与文本指令，输出四个动作之一（飞行、环顾、停想、宣布到达）；涵盖单无人机（接近、搜索、跟踪、搜索+跟踪）、多无人机（一个模型驱动多架，或指挥官+每架子智能体）以及真实无人机飞行，跨场景与模拟器变化。
Motivation（研究动机）
现有无人机 MLLM 评测存在三点局限：大多只在仿真中评测、只针对单架无人机、且假设目标从一开始可见且静止或路线已在指令中给出，因此结果能否迁移到真实无人机未知。
Insight（核心洞察）
MLLM 已能仅凭提示控制无人机，但其可靠性不只取决于感知，还取决于是否及时宣布到达以及动作延迟；小模型经合成数据微调后可在真实飞行中胜过前沿模型；多无人机时指挥结构比模型本身更重要。
Challenge（技术挑战）
  • 前沿模型延迟高（每步 1.4–3.5 秒），导致丢失移动目标
  • 小型开源模型即使到达目标也往往不宣布到达
  • 仿真结果向真实无人机迁移时延迟与硬件限制影响更大
  • 多无人机从单一上下文同时驱动多架效果差
  • 需在真实飞行中满足延迟与机载硬件约束
Analyze（问题分析）
作者构建 DroneCATS 基准，按目标可见性、目标运动、场景与模拟器变化系统改变条件，并用统一基于“宣布到达”的判据评分；通过分别统计成功率（SR）、到达率（OSR）、导航误差（NE）与每步延迟来分解失败原因，从而把失败归因于延迟、宣布到达行为与模型规模；多无人机则对比不同指挥结构。
Method（方法）
  • 提出 DroneCATS 基准，MLLM 通过四个动作单独控制无人机：飞行、环顾、停想、宣布到达
  • 单无人机套件覆盖接近、搜索、跟踪、搜索+跟踪四类任务，每类 20 个回合
  • 变化目标可见性、目标运动、场景与模拟器，并扩展到真实无人机
  • 加入多无人机套件：一个模型驱动多架，以及指挥官+每架子智能体结构
  • 评测十个 MLLM，包括四个前沿闭源模型、五个开源模型和一个自微调模型
  • 根据失败分析，用公开 RGB-D 图像合成无人机动作数据微调 2B 模型
Experiments（实验）
  • Gemini 3.7 Flash 平均成功率最高，且能到达目标并宣布到达；最佳模型随任务类型而变：两个静态目标任务为 Gemini 3.7 Flash，跟踪为 Gemini Robotics-ER 2，搜索+跟踪为 GPT-5
  • 四个前沿模型都能定位目标，移动目标上的差异来自延迟：GPT-5 与 Gemini Robotics-ER 2 每步 1.4 和 2.0 秒，另两个为 2.9 和 3.5 秒
  • 在 Qwen3.5 系列内，平均成功率从 2B 到 27B 单调上升
  • 微调的 2B 模型在仿真中成功率从 0% 提升到 31%，并在真实飞行中优于前沿模型
  • 多无人机：每个零样本模型作为“每架一个子智能体”的指挥官时成功率都高于从单一上下文驱动全部无人机；指挥成功率与通用 VLM 能力相关
  • 真实无人机结果总体与仿真一致，但延迟与硬件限制影响更大

Setting（研究设定）
利用人类操作视频与少量机器人示教，在冻结的世界动作模型上实现跨具身迁移，使机器人仅凭自身观测生成动作，无需人-机器人运动对应。
Motivation（研究动机）
机器人交互数据采集昂贵，而人类操作视频丰富多样；但形态、动作空间与控制机制差异使人手动作无法直接作为机器人监督，因此需要回答人类视频中哪些知识应跨具身迁移。
Insight（核心洞察）
完整人类操作序列包含支撑任务进展的物体交互关系与绑定于人体形态的具体运动实现；长时任务应先用时序扩展子任务组织为局部过程，并以因果束刻画子任务内应保留的上下文条件与交互依赖关系。
Challenge（技术挑战）
  • 人类与机器人在形态、动作空间和控制机制上的差异
  • 长时操作任务中子任务内应保留哪些信息未明确
  • 需在保留局部机制输出的同时維持对保留输入的非平凡响应性
  • 不依赖人-机器人运动对应关系生成动作
Analyze（问题分析）
作者从因果束视角分析子任务迁移，聚焦哪些上下文条件和交互依赖应被保留以支撑局部任务效果；将子任务定义为迁移发生的局部范围，并指出其本身不决定范围内应保留的信息。
Method（方法）
  • 从人类视频学习与操作相关的表征
  • 用机器人示教将这些表征落到任务级语义变量（条件、操作尝试、物体状态变化与效果）
