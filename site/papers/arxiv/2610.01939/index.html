核心洞察

将机器人原语组合为可执行 Python 程序，在程序内部完成条件判断、局部重试与持续状态维护，仅把显式请求的图像与状态反馈返回给 VLM，可以在不牺牲成功率的前提下大幅减少 LLM 调用与输入词元。

为什么值得看：它提供了在保持或提升机器人任务成功率的同时显著降低 LLM 调用与输入词元的可迁移接口设计（反馈驱动原语组合 + 选择性观测 + 持久程序状态），并通过轨迹与消融定位收益来源，对研究可执行动作生成、长时序反馈执行与推理效率优化的读者具有直接参考价值。

Setting（研究设定）
使用 GPT-6 Astra 作为规划器、冻结的 VLA 策略与经典机器人原语，在 LIBERO-PRO、RoboTwin 2.0、RoboCasa365 三个仿真基准的 700 个任务实例上，对比 PyRUA-Lean 交互式代码执行接口与 RPent 工具调用基线，无跨回合记忆。
Motivation（研究动机）
VLM 智能体通过视觉反馈与动作原语控制机器人时，重复的模型调用与冗余观测会带来大量词元开销；工具调用接口下依赖前序结果的操作通常需要额外 VLM 调用，中间结果不断累积进上下文，导致推理开销高。
Insight（核心洞察）
将机器人原语组合为可执行 Python 程序，在程序内部完成条件判断、局部重试与持续状态维护，仅把显式请求的图像与状态反馈返回给 VLM，可以在不牺牲成功率的前提下大幅减少 LLM 调用与输入词元。
Challenge（技术挑战）
  • 工具调用接口下依赖前序结果的操作需要额外 VLM 调用
  • 中间结果在对话中累积并被后续调用重复处理
  • 执行失败需要恢复与重试
  • 视觉观测冗余导致上下文膨胀
  • 如何在不牺牲成功率的前提下控制返回给 VLM 的信息量
Analyze（问题分析）
作者通过对比同一 GPT-6 Astra 规划器与相同底层原语下 PyRUA-Lean 与工具调用基线在三个基准 700 个实例上的成功率、LLM 调用次数、输入词元与推理成本，并借助轨迹与消融分析定位收益来源。
Method（方法）
  • 提出 PyRUA-Lean，基于 RPent 机器人栈与原语实现的交互式代码执行接口
  • 智能体将经典机器人原语与学习到的 VLA 策略组合成 Python 单元，在单元内执行条件检查与局部重试
  • 仅将显式打印的输出与被请求的相机图像返回给 VLM 用于重新规划
  • 通过 robo Python 对象与 python(code) 工具交互，每次交互 VLM 生成一个代码单元，运行时执行后返回反馈指导下一单元
  • 跨单元保持持久 Python 命名空间以保留变量与辅助函数，但评估不使用跨回合记忆
  • 未捕获异常终止当前单元并返回 traceback，异常前赋值的变量仍保留以便后续修正
  • 原语作用于机器人前，若任务已完成则终止该单元；外部看门狗执行两小时回合上限
Experiments（实验）
  • 在 LIBERO-PRO、RoboTwin 2.0、RoboCasa365 共 700 个仿真任务实例上，与使用相同 GPT-6 Astra 规划器和底层原语的工具调用基线比较
  • 在相同 LLM 调用预算下，PyRUA-Lean 将整体成功率从 63.1% 提升到 71.7%（约 14% 相对提升）
  • 在两者均解决的实例上，PyRUA-Lean 减少 49% 的 LLM 调用与 65% 的输入词元
  • PyRUA-Lean 在每个子套件上达到或超过工具调用的成功率，且在每项基准上成本更低
  • 消融分析表明更少的 LLM 调用是词元节省的主要来源；收益在无 VLA 策略或无操作指南时仍存在，但在 VLA 主导的任务上减弱
Limitations（局限）
  • 大规模多样任务、训练运行与物理机器人性能尚未测试
  • 比较评估的是完整接口，未完全分离原语组合、持久状态与选择性反馈各自的贡献
  • 未来工作将解决这些局限，测量物理机器人上的执行延迟与恢复，并考察原语粒度与已验证例程的跨回合复用对成功率、推理成本和适应性的影响
