Setting（研究设定）
在机器人本体嵌入式板（如 Jetson AGX Orin）上运行视觉-语言-动作模型进行操作任务；每个控制步将数百个视觉 token 与语言指令输入 LLM 骨干，prefill 延迟随输入 token 数增长，需在实时约束下决定跳过 token 的处理方式。
Motivation（研究动机）
移动操作臂与人形机器人无法依赖工作站或远程服务器，必须在机载嵌入式板实时推理；视觉 token 约占输入序列 90%，是计算与延迟的主要来源，现有免训练加速方法对每个被跳过的 token 只采用剪枝或只采用 KV 复用之一，缺乏对二者选择依据的研究。
Insight（核心洞察）
被跳过 token 该复用还是剪枝取决于其 drift，即自缓存计算以来浅层值的变化；drift 低于阈值时复用不劣于剪枝，超过阈值后复用误差最高达剪枝的 4.4 倍，阈值与骨干相关且可通过同一 token 级诊断逐骨干标定。
Challenge（技术挑战）
  • prefill 阶段在嵌入式硬件上是计算受限的，延迟随输入 token 数增长
  • 远程卸载受网络延迟波动与断连影响，单次延迟或丢包即阻塞控制环
  • 复用陈旧 KV 缓存会通过注意力把错误上下文传给被重算 token，导致失败
  • 纯剪枝在预算缩小时丢失任务相关区域，性能随预算下降而持续退化
  • drift 阈值依赖骨干、任务与场景变化速度，难以固定
Analyze（问题分析）
作者设计 token 级诊断实验：对同一批 token 分别做一次复用和一次剪枝，将各自产生的动作与全量重计算对比。结果表明复用与剪枝的优劣由 drift 决定，且阈值可逐骨干标定；据此把两类逐 token 信号分工：缓存有效性（drift 低于阈值且有界缓存年龄）决定复用还是剪枝，重要性（动作解码 token 对其注意力）决定有限重算预算的分配方向。
Method（方法）
  • 用 token 级诊断标定每个骨干的 drift 阈值，低于阈值的缓存视为有效
  • 缓存有效性需同时满足 drift 低于阈值与缓存年龄有界
  • 按固定重算预算 B 优先重算缓存无效的重要 token
  • 其余缓存有效的 token 复用，剩余 token 剪枝
  • 由于重算 token 数固定，预算直接决定 prefill 延迟；剪枝-only 与复用-only 是该方法两个极端
Experiments（实验）
  • 在 LIBERO 与 SimplerEnv 两个基准、两个 VLA 骨干上评测，延迟在 Jetson AGX Orin 上测量
  • 平均成功率与全量重计算相差不超过 3 个百分点，Jetson AGX Orin 上 prefill 延迟最多降低 48%
  • 仅重算 7% 视觉 token 时，在 LIBERO-Object 上超出最强基线 24.4 个百分点
  • 预算扫描中 drop-all 在 B=18 时降至 22.4%，keep-all 在 B=18 时降至 0.0%，TRIAGE 在 B=18 时仍达 75.8%
  • SimplerEnv 上 TRIAGE 平均 54.5%，全量重计算为 54.8%，SpecPrune-VLA 与 VLA-Pruner 分别落后 4.2 与 6.1 个百分点
  • Jetson 上 prefill 为全量重计算的 0.74 倍，端到端与 p99 延迟最低
Limitations（局限）
  • 超参数（δ、T、κ、λ、μ）为经验设定而非从第一性原理推导
  • 区分复用与剪枝的 drift 阈值不固定：OpenVLA 上 drift 从 0.5 起复用变有害，OpenVLA-OFT 上从 0.3 起，且可能随骨干、任务与场景速度漂移，需要部署期自适应调整
  • TRIAGE 仅通过 drift 在变化发生之后检测变化，未利用光流、视频编解码运动向量或学习式 patch 选择器提前区分静态与运动区域
与你的研究关系
该工作直接针对 VLA 模型在真实机器人嵌入式平台上的实时推理，涉及可执行动作生成的延迟约束、视觉 token 计算削减与 KV 缓存复用，属于系统优化与具身智能部署的交叉方向；其 token 级诊断与预算化重算机制可迁移到实时控制与模型压缩研究。

证据主要来自摘要与全文节选，部分方法细节与完整实验表格未全部呈现；drift 阈值等具体数值仅来自节选片段，未涵盖全部骨干与任务的完整结果。

被跳过 token 该复用还是剪枝取决于其 drift，超过阈值后复用误差最高达剪枝的 4.4 倍：reusing tokens below a drift threshold was no worse than pruning them, whereas beyond it, reuse yields up to 4.4x the action error of pruning
TRIAGE 将 token 分为重算、复用与剪枝三类，剪枝-only 与复用-only 是其两个极端：TRIAGE recomputes a fixed budget of tokens, prioritizing important tokens with invalid caches, reuses every other token with a valid cache, and prunes the rest; prune-only and reuse-only methods are the two extremes of this partition
预算固定重算 token 数，因此直接决定 prefill 延迟：Because the budget fixes the number of recomputed tokens, it directly sets the prefill latency.
